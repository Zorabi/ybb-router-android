# 开发说明

## 结构

| 文件 | 职责 |
| --- | --- |
| `MainActivity.java` | 原生首页、设备管理、游戏目录、区服、会员及路由器管理 |
| `LoginActivity.java` | 百度官方网页登录，完成后回到原生管理界面 |
| `ApiClient.java` | HTTPS 请求、官方请求头、登录令牌交换及认证失败重试 |
| `SessionStore.java` | 使用 Android Keystore 的 AES-GCM 加密保存会话令牌 |
| `Repository.java` | 原生缓存、配置合并、接口数据裁剪和原子文件写入 |
| `GameRules.java` | 平台、搜索、设备类型、配置合并及加速消息规则 |
| `FavoriteRecords.java` | 当前快照中未发现的常用记录及最后发现信息 |
| `AccelerationQueue.java` | 本次进程内的单目标替换队列、取消与指令发送边界 |
| `GameSwitchOperation.java` | 可模拟验证的停止确认、配置核对和自动启动流程 |
| `PreferenceBackup.java` | 本地偏好备份格式、字段白名单、版本及大小校验 |
| `NativeUi.java` | 深浅色、间距、原生控件和交互状态 |

应用标识保持 `dongx.ybbrouter`，以便从初始网页版本覆盖升级并保留登录 Cookie。只在登录时显示 WebView；原生管理页不会加载或运行 H5 管理代码，也不使用 JavaScript bridge。

## 接口

依据 2026-11-07 实际读取的小米 WiFi 5.9.0 插件入口和游帮帮网页资源适配，2026-11-20 按当日网页资源重新核对配置接口。以下为观察到的实现，并非官方公开兼容承诺。

接口根地址为 `https://ybb.baidu.com/api/v1/server/`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `auth/token` | 使用当前应用内的百度登录 Cookie 换取管理令牌 |
| GET | `router/bind?brand=xiaomi` | 读取已绑定路由器 |
| GET | `router/device` | 读取连接、设备、插件版本和加速状态 |
| GET / POST | `router/config/game` | 读取 / 保存平台游戏配置与设备类型覆盖 |
| GET | `game/list?type=…` | 获取平台游戏目录 |
| GET | `gamelist/detail?game_id=…` | 获取区服及游戏详情 |
| POST | `router/message` | 发送 `start_speed` 或 `stop_speed` 指令 |
| GET | `user/info`、`goods`、`client/pop` | 账号展示、会员状态及可领取活动 |
| PATCH | `client/pop/{id}` | 用户主动确认后领取当前可用权益 |
| DELETE | `router/unbind/{id}` | 用户主动确认后解绑路由器 |
| GET | `user/logout`、`notice/list` | 退出登录 / 读取公告 |

认证要求 Bearer 令牌及稳定的 `X-Client-Cuid`。本机随机生成客户端标识，不使用硬件标识。请求使用与插件相同的渠道与协议版本头。

配置接口自 2026-11-20 起按官方网页资源核对的约定：

- 保存 `router/config/game` 的请求体为 `{"type":"game","content":{…完整配置…}}`，`content` 为包含各平台选择与 `device_type` 覆盖的完整配置对象；直接提交裸配置对象会被服务端接受但不落库。
- 从未保存过配置的账号，读取 `router/config/game` 返回 `result:null`，需按空配置处理（官方前端同样使用 `result || {}` 兜底）。
- 区服代码以下发的 `region_list` 为准（当前为大写，如 `JP`、`HK`、`AUTO`），保存与下发指令时保留原始值，不做大小写转换。

## 状态与安全

- 所有管理请求使用 HTTPS，只向固定的游帮帮域名发送账号 Cookie 和令牌，拒绝接口重定向。
- 不添加任意 URL、任意 JavaScript 或外部 Intent 注入入口；登录 Activity 不向其他应用导出。
- 令牌保存在 Keystore 加密的应用私有存储中。会话、目录和设备缓存均不进入云端备份或设备迁移。
- 用户信息只缓存显示所需的昵称与头像地址，游戏目录只缓存搜索和选择必需字段。
- API 日志只记录无参数的路由模板、HTTP 状态或错误码，不记录请求体、响应正文、令牌、Cookie、IP 或 MAC。成功日志仅在启用 `YbbApi` DEBUG 日志时输出。
- 配置保存前重新读取服务端数据，只合并当前平台或指定 MAC 的修改，保留其他平台与未知字段。
- 发送启动指令前重新核对设备 IP 与 MAC、最新游戏配置、插件兼容性及其他设备的加速状态。
- 只有用户确认后才停止其他正在加速的设备；需要等待停止确认，再保存配置或启动目标设备。
- 不自动重试超时的修改请求，避免重复执行。只对服务端明确拒绝的认证请求重新登录后重试。
- 启动先显示本地设备缓存，再后台同步路由器、配置与设备状态；数据相同时保留现有列表，实际变化时保留搜索控件、焦点、光标和滚动位置，只替换发生变化的设备卡片；计时等动态字段不触发列表重建。
- 首页可见时定期读取状态，进入后台后停止轮询。命令提交与路由器实际生效分别展示，超时提示刷新核实。
- 登出清除应用自己的原生缓存、令牌、Cookie 与网页存储，不影响手机浏览器或小米 WiFi 的数据。

## 本地偏好

常用设备、设备别名、最近游戏和按游戏记忆的区服保存在应用私有的 `shortcuts` SharedPreferences 中，不发送到服务端，退出登录时保留。

- 常用设备以路由器序列号和规范化的小写 MAC 为键，与 IP 无关；设备列表刷新后使用当前 IP。设备未出现在列表中时展示不可加速的历史简卡，不认定它已经离线，也不自动删除标记。
- 成功刷新设备列表时更新常用设备名称、类型和最后出现时间，时间写入间隔至少一分钟。旧记录缺失的信息不会根据缓存推算。
- 手动清理只列出当前路由器下未在最新列表中出现的常用记录，默认不勾选；确认移除时一并删除名称和时间。无法可靠区分暂时离线与更换 MAC。
- 最近游戏按设备类型分别保存，成功保存游戏与区服后更新顺序，最多保留 6 项。移除只影响本地记录，并抑制当前游戏自动补回；再次成功保存时解除抑制。
- 设备别名按路由器和 MAC 保存，只在本机展示；空名称恢复原名，搜索同时匹配原名。
- 每款游戏成功保存后记住原始区服代码，选择区服时将上次使用的可用项前置；不自动提交配置，过期区服不替换成其他区服。
- 备份格式为 `dongx.ybbrouter.preferences`、版本 1，通过系统文件选择器导入导出。文件最大 1 MB、最多 5000 项；只接受已知偏好键及匹配的数据类型，最近游戏最多 6 项。校验后按设备、别名、游戏及区服统计摘要；冲突按设备或游戏平台分组，默认保留本机，用户勾选的组才采用备份。预览后本机相关偏好发生变化时拒绝恢复，元数据不作为冲突且最后发现时间取较新值。未知偏好键或版本使整份导入失败，登录凭据和服务端配置不参与备份。
- 设备更多菜单打开期间保留当前卡片，避免后台刷新打断操作；菜单关闭后展示最新数据。
- 加速阶段区分核对、发送和等待确认；确认超时提供刷新入口，不自动重发可能已执行的指令。

## 本地验证

56 项 JVM 测试覆盖配置与协议规则、列表刷新、区服偏好排序、最近游戏快捷选择、未发现的常用记录、备份往返、恢复冲突及无效文件拒绝、日志路径脱敏，以及排队切换的超时、取消、替换、设备身份变化和保存失败保护。

真机验收应检查：冷启动缓存、游戏搜索与区服、账号页、断网、深浅色、Tab 焦点、返回导航，以及用户选定设备的实际启动与停止。通过构建和接口读取不代表已验证加速线路效果。


2026-11-07 已在用户连接的安卓手机上检查原生首页、17 台设备读取、PS5 的 595 款游戏目录、拼音搜索、当前游戏区服展示、账号会员页、页面返回、深浅色切换及 Tab 焦点。深浅色测试后恢复了原系统浅色设置。此轮界面验收未修改游戏配置；后续已通过原生界面验证 PS5 的实际加速启动。


0.2.1：加速计时使用服务器时间作为基准，结合单调时钟每秒更新，不依赖状态请求完成。启动与停止按钮统一为蓝底白字、固定尺寸；提交请求和等待路由器确认期间，当前按钮显示原生 ProgressBar，其他按钮的禁用状态保留白色文字。真机已观察到实际启动成功及启动、停止加载动画。

本轮界面调整已在连接的安卓手机上检查首页、账号页、深浅色外观和键盘焦点；当前系统显示设置下，账号信息、会员卡、服务入口、退出登录及版本信息可在一屏内显示。小屏幕、大字体或额外会员活动内容较多时仍保留滚动。未通过更改真实设备 MAC、清除用户常用记录或重新下发加速指令来验证本轮变更。

0.2.2：适配服务端 2026-11 变更的配置接口。保存配置改用 `{"type":"game","content":…}` 信封（此前提交裸配置对象会被静默丢弃）；读取配置对 `result:null`（从未保存过配置）按空配置处理，不再中断启动与保存流程；区服代码保留服务端原始大小写；`ApiClient` 增加 `YbbApi` 标签的请求结果日志（不含令牌与 Cookie），便于排查协议变化。已在真机验证配置保存落库、启动加速与停止加速的完整链路。

0.3.0：增加固定签名配置、偏好备份恢复、设备别名和按游戏区服记忆，改进缓存与加速阶段提示并缩减 API 日志。Debug、Release 构建及 JVM 测试、Lint 已在本机检查；已覆盖安装至连接手机，系统文件选择器、布局及实际加速过程尚未完整真机复验。签名迁移与其他机器的配置方法见 [固定签名说明](SIGNING.md)。

排队切换通过应用级单目标队列与原有命令互斥，共享停止、启动确认状态。只在确认前序指令后执行后续任务；保存后读取配置验证游戏和区服，再下发启动。MAC、IP、路由器、设备类型和插件兼容性在关键步骤重新校验，不自动停止其他正在加速的设备。已发送的停止会继续等待确认，期间的新选择不会重复发送停止；已发送的启动不宣称可撤销。任务不落盘，不跨进程恢复；进入后台后不保证持续运行。失败会清空后续队列，只有用户再次选择才会重试。

新增切换流程使用模拟后端验证操作顺序与失败边界，尚未通过下发真实停止、保存与启动指令进行真机链路验收。

设备卡片先展示最多 3 款最近游戏及保存的区服，完整目录保留最近 6 款排序和单项移除。重复选择相同游戏与区服不再执行停止或保存；明确要求启动的空闲设备仍会开始加速。首页复用搜索框和未变化的卡片，常用记录缺席时使用独立的不可操作历史卡片，MAC 回到列表后自动恢复正常卡片。
